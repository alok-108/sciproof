# Multi-Step Pipeline Verification (`sciproof pipeline`)

In real-world computational research and machine learning workflows, an experiment is rarely a single monolithic script. It is structured into multiple stages:

$$\text{Data Prep} \longrightarrow \text{Feature Extraction} \longrightarrow \text{Model Training} \longrightarrow \text{Evaluation}$$

`sciproof pipeline verify` ties individual stage manifests together into a verifiable Directed Acyclic Graph (DAG) and proves **end-to-end cryptographic chain-of-custody**.

---

## Defining a Pipeline (`pipeline.toml`)

Create a `pipeline.toml` that lists each step's manifest and prerequisite dependencies:

```toml
[pipeline]
name = "genomics_variant_calling"

[[steps]]
name = "alignment"
manifest = "step1_align.sciproof.json"

[[steps]]
name = "variant_calling"
manifest = "step2_call.sciproof.json"
depends_on = ["alignment"]

[[steps]]
name = "annotation"
manifest = "step3_annotate.sciproof.json"
depends_on = ["variant_calling"]
```

---

## Verifying the Pipeline

Run:

```bash
sciproof pipeline verify pipeline.toml
```

Output:
```text
SciProof Pipeline: genomics_variant_calling
Overall Verdict: PASS

Steps:
  [PASS] alignment (step1_align.sciproof.json)
      reason: all declared inputs and outputs match recorded SHA-256 hashes
  [PASS] variant_calling (step2_call.sciproof.json)
      reason: all declared inputs and outputs match recorded SHA-256 hashes
  [PASS] annotation (step3_annotate.sciproof.json)
      reason: all declared inputs and outputs match recorded SHA-256 hashes
```

---

## Cryptographic Chain-of-Custody

If intermediate files generated by step 1 (`alignment`) are modified before step 2 (`variant_calling`) consumes them, `sciproof pipeline verify` detects the mismatch:

```text
SciProof Pipeline: genomics_variant_calling
Overall Verdict: FAIL

Steps:
  [PASS] alignment (step1_align.sciproof.json)
      reason: all declared inputs and outputs match recorded SHA-256 hashes
  [FAIL] variant_calling (step2_call.sciproof.json)
      reason: chain-of-custody broken by modified intermediate files
      chain-of-custody break: input 'aligned.bam' sha256 a1b2c3... does not match output from prerequisite step 'alignment' (e4f5a6...)
```

This guarantees that every dataset consumed downstream originated unmodified from verified upstream computations.
